# 수처리 특이 시나리오 정의

ENGRA가 수처리 Plant 데이터에서 감지해야 할 특이사항을 정의한다.
ASU `scenarios.md`와 같은 서식을 쓰고, 같은 방식으로 모의 데이터 생성기의 입력이자
감지 성능(포함률) 측정의 기준이 된다.

- 태그 정의: [`tag_master.csv`](tag_master.csv) (계측 태그 65점)
- 설비 정의: [`PLANT_SPEC.md`](PLANT_SPEC.md)
- **ASU 자산과 분리** — 이 문서와 태그 마스터는 `docs/water/` 아래에만 있다.
  엔진 정본인 `docs/tag_master.csv`와 `docs/scenarios.md`는 건드리지 않는다
- 1~4번은 CLAUDE.md「이상 시나리오(데모용 우선순위)」를 서식에 맞춰 옮긴 것
- 5~10번은 냉각탑 계통·TMS 계통 추가분

## 제약과 주의

**① 생성기는 링크를 1단계만 전파한다.**
ASU `scenarios.md`에 기록된 `applyLinks` 동작이다 — `add[]`를 원본에서 계산해 한 번에 더하므로
2단계는 닿지 않는다. `#5`가 여기 걸린다.

```
FI-302 ──links──▶ LT-03A, AT-04        ← 여기까지 간다
LT-03A ──links──▶ FI-301A              ← 여기는 안 간다
```

물리적으로는 냉각탑 수요 증가가 탱크 수위를 낮추고 그것이 UF 증산으로 이어지는 게 맞지만,
**정답지는 데이터에 맞춘다.** `#5`의 영향 태그는 `FI-302`·`LT-03A`·`AT-04` 3개까지만 적는다.
ASU에서 `#3`·`#11`이 선언 7개 / 실제 3개였던 것과 같은 문제이고, 같은 방식으로 처리한다.

**② 드리프트 진폭이 알람선을 침범하면 안 된다.**
ASU `LI-806` 결함(근무당 오탐 1.00건)의 원인이다. 진폭은 정상범위 폭 기준으로
**1단 4.2% · 2단 8.4% · 3단 16.8%**(주 드리프트 + 보조 0.4배)이고, `nominal ± 진폭`이
`H`/`L`을 넘으면 시나리오를 안 넣어도 상시 알람이 뜬다.
→ 현재 `tag_master.csv` 65태그 전수 검사 **침범 0건**. 태그를 추가하거나 한계값을 바꾸면 다시 검사할 것.

**③ 계열 구분은 기기 태그로만 된다.**
계측 태그를 CLAUDE.md 표기대로 두기로 해서 `VPT-01`·`TUR-01`·`LT-02`는 3계열 대표값 하나다.
`#2`(막 파손)는 어느 계열인지 계측값으로 못 가린다. 계열을 보여야 하면
`JI-201A/B/C`·`ZI-201A/B/C`·`FI-203A/B/C`를 써야 한다.

**④ TMS 계통은 실설비 확인 전이다.**
`PH-02`·`QI-801`~`QI-804`·`FI-603` 6점은 CLAUDE.md에 근거가 없다. TMS는 공공수역 **방류** 지점에
붙는 법정 설비인데 CLAUDE.md는 "상등수 재이용"이라고만 돼 있어 방류 경로 자체가 정의돼 있지 않다.
`#7`·`#8`은 이 6점 위에 서 있으므로, 실설비에 TMS가 없으면 두 시나리오와 6개 태그를 같이 뺀다.

**⑤ 간헐 운전 태그는 태그 마스터에서 뺐다 — ASU 코드를 안 고치기 위해서다.**
`JI-401`(CIP 히터 전력)·`CI-906`(Citric Acid 주입률)·`PSH-01`(흡인 고압 스위치)을 제거했다.

셋 다 비운전 구간에 값이 **진짜로 한 점에 멈춘다**(0 kW · 0 L/h · 0). 고착 검출기는
20분간 변동이 `max(q, 노이즈×0.05)` 이하면 **중요도 '상'으로 무조건 보고**하므로, 세정을 안 하는
근무에서는 이 세 태그만으로 **오탐 예산(근무당 3.0건)을 혼자 넘긴다.**

운전모드 플래그로 검출을 막는 방법은 `engine/`을 고쳐야 해서 버렸다 — ASU 가 같은 코드를 쓴다.
대신 **세 태그를 빼고**, `TT-01`(CIP 세정온도)은 남겼다. 세정을 안 할 때도 탱크가 외기를 따라
실제로 움직이므로 고착으로 잡히지 않는다(생성기 `AMB` 에 `TT-01:[0.55, 0]` 으로 넣었다).
`#10`(CIP 세정)의 신호는 `VPT-01` 하강 + `TT-01` 상승이라 세 태그가 없어도 성립한다.

**⑥ 외기 태그 이름을 ASU 와 똑같이 뒀다 — 이것도 ASU 를 안 고치기 위해서다.**
`engine/core.py:206` 의 `NOISE_TAGS = ("TI-101", "MI-102")` 는 모듈 상수라 ASU·수처리가 함께 쓴다.
수처리 외기 태그를 `TI-001`·`MI-001` 로 두면 이 목록에 안 걸려 **드리프트 검출의 외기 보정이
통째로 건너뛰어진다.** 그렇다고 목록을 수처리 태그로 바꾸면 ASU 가 깨진다.

그래서 수처리 외기 태그를 `TI-101`(외기 온도)·`MI-102`(외기 습도)로 **같게** 명명했다.
**엔진 코드 수정이 0 줄**이고 양쪽 다 정상 동작한다. 태그 마스터와 DB(`ENGRA_DB`)가 공정별로
분리돼 있어 이름이 겹쳐도 데이터가 섞이지 않는다.

`VPT-01` 이 수온에 −0.50 감도라 이 보정이 실제로 중요하다 — 보정이 없으면 막 오염 드리프트와
수온 일변동이 섞여서 `#1` 의 조기 검출이 무너진다.

**⑦ 주입 크기는 「공칭 + 베이스라인 진폭」 예산 안에서 정한다 — 문서값을 그대로 못 쓴다.**

위 표의 「크기」 칸은 공칭값 기준으로 적은 값이다. 실제 데이터에는 자체 드리프트(정상범위 폭의
최대 16.8%)·노이즈 3σ·외기 일변동·유입 연동이 겹쳐 있어서, 공칭값에 문서 진폭을 그대로 더하면
알람선을 넘는 시나리오가 나온다. **알람 전에 잡는다가 전제인 시나리오가 알람을 울리면 전제가 깨진다.**
그래서 ② 를 확장한 규칙을 둔다.

```
미발생 시나리오 : 공칭 + 베이스라인진폭 + 주입 ≤ H   (L 쪽도 같게)
발생   시나리오 : 공칭 − 베이스라인진폭 + 주입 >  H   (최악에도 울린다)
```

이 규칙으로 다시 잰 결과 `#1`·`#3`·`#5`·`#6`·`#7`·`#9`·`#10` 의 크기를 조정했다. 특히 두 건은
크기 조정이 아니라 **전제 자체가 틀렸던 것**이다.

- **`#1` — 문서의 +18 kPa 를 넣으면 TMP 알람(H 125)보다 펌프 전력 알람이 먼저 울린다.**
  선언 연동 `VPT-01 → JI-201A`(0.60) 때문에 TMP 가 오르면 Process Pump 전력이 따라 오르고,
  `JI-201A` 는 공칭 9.2 에 H 가 11 이라 여유가 1.8 밖에 없다. 주입 9.0 에서 최대 10.94 다.
  **TMP 만 보고 크기를 정하면 안 된다 — 연동이 닿는 태그의 한계까지 봐야 한다.**
- **`#10` — 문서의 TMP 122 → 105(−17)는 「`#1` 로 122 까지 올라가 있는 상태」를 전제한 값이다.**
  생성기는 `#1` 과 `#10` 을 각각 독립으로 배치하므로 기준선이 공칭 104 고, 여기서 −17 을 내리면
  L(90)을 뚫는다. **세정 자체가 알람을 만드는 것은 「계획 작업」의 정의에 어긋난다.** −5.8 로 줄였다.

`#9` 는 이 규칙만으로 정해지지 않았다. `LT-07` 은 H 85 · HH 92 로 둘 사이가 7 인데
베이스라인 진폭이 6.96 이라, **H 를 확정 초과시키면 HH 도 같이 건드리게 된다.** 처음에는
통상 86%(주입 38)로 뒀는데 **헤드리스로 실제 근무를 생성해 보니 알람이 안 떴다** — 그 근무의
베이스라인이 아래로 몰려 79% 에서 멈춘 것이다. 「발생」이 전제인 시나리오가 절반의 확률로
미발생이 되면 통합테스트 판정이 흔들린다. 주입을 44 로 올려 최악에서도 85.04(H 확정)가
되게 하고, 베이스라인이 높은 근무에서 HH(92)까지 가는 쪽을 택했다. 어느 쪽이든
「상한 돌파」라는 뜻은 같고, 정답지는 실측을 적으므로 거짓이 되지 않는다.

**⑧ 생성기에 DCS on-delay(10초)를 넣었다.**

알람 판정이 구간 최대/최소만 보던 때는 `#8`(4초 스파이크)이 정답지에 **「발생 · `QI-801` HH」**
로 적혔다. on-delay 미달이라 알람이 안 뜬다는 것이 `#8` 의 존재 이유인데 정반대로 기록된 것이다.
한계 초과가 10초(5샘플) 이상 이어져야 알람으로 세도록 고쳤다. ASU 생성기 `#12`(999 ppm 스파이크)도
같은 구조지만 **ASU 파일은 손대지 않았다** — 담당이 다르고, 고치면 ASU 측정치가 전부 무효가 된다.

**⑨ `CI-909` ↔ `TUR-03` 연동 방향을 뒤집었다.**

원래 `TUR-03 → CI-909:-0.50`(상등수 탁도가 오르면 Polymer 주입률이 내려간다)로 선언돼 있었는데,
원인과 결과가 뒤집혀 있다. 응집제를 덜 넣어서 탁도가 오르는 것이지 그 반대가 아니다.

방향이 틀린 것만이 문제가 아니다. `#7` 이 `TUR-03` 을 +13.5 올리면 `CI-909` 가 −2.89 밀려
**2.8 → −0.09 로 음수가 되고, 물리 클램프에 걸려 0 에 붙는다.** 주입률이 0 에 고정되면
⑤ 에서 뺀 간헐 운전 태그와 똑같이 **고착 검출기에 중요도 '상' 으로 잡힌다** — 오탐이다.
`CI-909 → TUR-03:-0.50:180` 으로 바꿔 원인이 결과를 끌게 했다.

### 통계 문턱값 — 엔진 확정값을 그대로 쓴다

공정과 무관한 엔진 상수다(`engine/검출기준.md`). 수처리라고 바꿀 이유가 없고,
바꾸면 ASU 와 같은 코드를 쓰므로 ASU 측정치가 전부 무효가 된다.

| 검출기 | 문턱값 |
| --- | --- |
| 한계선 교차 | `hi > H` / `lo < L`, 최소 1블록(30초) |
| **드리프트** | `k ≥ 3.5` **AND** `|r| ≥ 0.60`, 창 60·120·240·720분 |
| 레벨 시프트 | `k ≥ 3.0`, 앞뒤 중앙값 비교, w=10분 |
| 헌팅 | `mad비 ≥ 3.0` 이 60초 이상 연속 |
| 순간 이탈 | `z ≥ 8.0` **AND** 지속 ≤ 2분 |
| 임계 근접 | `frac ≥ 0.85` 가 30분 이상 연속 |
| 고착 | 20분간 변동 ≤ `max(q, 노이즈×0.05)` |
| 상관 이탈 | `links` 선언 쌍만, `|r| ≥ 0.50` |

산포는 평균·표준편차가 아니라 **MAD × 1.4826** 을 쓴다(이상값에 안 끌려가게).
블록 30초로 접되 `lo`·`hi` 를 남겨 3초짜리 스파이크가 평균에 묻히지 않게 한다.
