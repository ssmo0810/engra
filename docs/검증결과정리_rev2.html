1.검증 환경 — 모사 데이터를 썼고, 이렇게 만들었습니다

이 폴더의 데이터는 전부 모사(가상) 데이터입니다. 사내 원본 데이터·실제 태그 체계·시스템 화면을 일절 사용하지 않았습니다. 대신 구조와 난이도를 실제와 같게 맞췄습니다 — 평가 기준이 말하는 「실제 업무 데이터와 유사한 구조·같은 난이도」에 대응한 방식은 다음과 같습니다.

무엇을어떻게 실제와 유사하게 맞췄나
태그 마스터 53점 ASU(공기분리장치) 공정을 현장 경험이 있는 운전원이 직접 명세 — 태그별 정상값·정상범위· LL·L·H·HH 알람 한계·드리프트/노이즈 단계·태그 간 연동 관계까지. 주입한 변화가 연동 태그로 전파됩니다
데이터 규모 실제 근무 한 구간과 같은 조건 — 태그 53점 × 12시간 × 2초 주기 = 근무당 1,144,800점 (약 36MB). 배선 확인용 소형 데이터가 아닙니다
특이 시나리오 24종 헌팅·드리프트·파과·고착·서지 전조·상관 붕괴 등 실제 공정에서 문제가 되는 유형을 형태·크기·지속·중요도·판단 근거까지 정의. 알람에 걸리지 않는 13종과 알람이 울리는 7종으로 나눠 두 경로를 모두 시험하고, 계획된 정상 작업 2종·플랜트 정지/Trip 2종을 더해 24종입니다
현실적인 어려움 외기 온습도의 24시간 일주기 연동, 같은 태그에 두 시나리오가 겹치는 동시 발생, 근무 경계를 넘어 이어지는 변화까지 반영 — 검출이 쉬워지는 쪽이 아니라 어려워지는 쪽으로 만들었습니다
재현성 생성기는 브라우저 단일 파일로 동작하며 seed 고정 시 같은 데이터가 재현됩니다. 생성기 자체도 데이터 세트에 포함(asu_dcs_overview.html, 소스 zip 안)
자를 먼저 검증했습니다. 정답지를 기준으로 채점하므로 정답지가 틀리면 전부 틀립니다. 시나리오를 하나도 넣지 않은 같은 seed 근무와 대조해, 정답지가 「영향 태그」로 적은 태그가 실제로 움직이는지 24종 전수 확인했습니다 — 2개 시나리오가 실제 전파보다 넓게 적혀 있어 정정했고, 좁힌 정답지로 재채점해도 수치는 바뀌지 않았습니다.

3.조건을 바꿔가며 시험한 결과

조건결과확인한 내용
데이터가 많을 때통과 태그 53점 · 12시간 · 114만 점 — 적재 3.2초 + 검출·초안 틀 2.2초 실측
검출이 맞는가
(독립 채점)		통과 검출기를 만든 사람과 무관하게 생성한 데이터·정답지로 채점 — 주입 건 포함률 기준 2근무 22/22 · 랜덤 6근무 46/46 (100%), 종 커버 20/20(랜덤 21/21). 시각 일치도 IoU 0.73/0.69, 검출 지연 중앙 −2분/−0분, 알람보다 최대 706분 먼저. 오탐 근무당 1.0/1.8건 — 전부 주입 종료 직후 「복귀」 구간이라 이를 빼면 0건
결함이 없을 때
(정상 데이터)		통과 시나리오를 하나도 넣지 않은 정상 14근무(1,600만 점)에서 검출 이벤트 0건 · 초안 항목 0개 — 엔진이 스스로 만들어내는 오작동이 없습니다
형식이 어긋난 값이
섞였을 때		통과 기본은 첫 오류에서 줄 번호와 함께 멈추고, --skip-bad-rows 는 546행을 건너뛰며 보고 — 깨진 행이 1%를 넘으면 잘못된 파일로 거부. 시험 중 조용한 오염 1건(천 단위 콤마)을 발견해 걸러내도록 고쳤습니다. NaN·Infinity·시간대 붙은 시각도 이유를 밝히며 거부합니다
값이 비어 있을 때통과 5,724행 빈 값 + 2시간 연속 결측 — 건너뛰고 「계측 결측 — 태그·시각·분」 항목을 초안 맨 앞에 넣습니다. 결측 경계에서 가짜 이벤트(아티팩트)가 생기지 않는 것 확인
오래 쓸 때
(50일 100근무)		통과 DB 605.8 → 611.3MB — 7근무째부터 평평(원본 3일 회전). 검출 시간 평균 18.3초로 누적 저하 없음. 누적 이벤트 2,400건 · 확정 일지 100건 실측
규모를 늘릴 때
(태그 16배)		통과 53점 2.8초 → 848점 108.3초, 대략 n^1.3 — 제곱이 아닙니다(상관 검출이 전수 조합이 아니라 태그 마스터의 연결 쌍만 봄). 검출은 근무당 한 번이라 848점에서 2분은 여유입니다
AI 판단통과 7근무 실측 — 과거 조치 후보 50건 → 채택 33·기각 17(판정 사유 100% 기재), 중요도 재판정 19%, 없는 조치 지어냄 0건, 본문 숫자 423개 중 환각 0개, 같은 근무 2회 재현 9/9 일치. AI 연결이 없으면 초안 생성을 멈추고 표시합니다
세 가지 수치를 구분해 밝힙니다. 자체 점검(만든 사람의 시험지)은 20/20 · 오탐 0.8건이었습니다. 독립 채점에서는 처음에 포함률 98% · 오탐 12배 · 1종 미검출로 달랐고 — 외기 일주기 오인과 근무 경계 드리프트, 결함 2건이 드러났습니다. 이를 수정하고 재측정한 값이 위 표(100% · 복귀 제외 0건)입니다. 독립 측정이 필요했던 이유가 그대로 증명된 셈이라 세 값을 모두 남깁니다.

4.재현 방법 — 심사위원이 직접 돌릴 수 있습니다

파이썬 3.10 이상만 있으면 설치할 것이 없습니다(외부 의존 0). 소스는 「02. 결과물 / 2. 결과물 원본」의 zip 을 풀고, 데이터는 이 폴더의 데이터세트/ 를 씁니다.

export ENGRA_LLM=off PYTHONIOENCODING=utf-8 ENGRA_DB=/tmp/score.db
python3 app/cli.py init
for f in data/asu_shift_*_12h.csv; do python3 app/cli.py ingest "$f"; done
python3 app/cli.py run 2026-08-21-day && python3 app/cli.py run 2026-08-21-night
python3 tools/score.py data/asu_answer_key.json      # 독립 채점 — 위 표의 수치가 나옵니다

같은 흐름을 화면으로 보시려면 공개 앱의 파이프라인 화면에 데이터세트/ 의 CSV 를 올리셔도 됩니다. 정답지 대조는 관리 화면에서 정답지 JSON 을 올리면 표로 나옵니다.

5.잘 되지 않았던 조건 — 일곱 가지

실패 조건을 감추지 않고 적습니다. 한계를 알고 있다는 것이 이 문서에서 수치만큼 중요하다고 생각합니다.

  1. 플랜트 정지·Trip 에서는 초안이 폭주합니다 계획 정지 시나리오에서 초안 항목이 39건까지 늘었습니다. 정지는 모든 태그가 함께 움직이는 상황이라 항목 단위 검출이 전부 반응한 것입니다. 지금은 짧은 시간에 태그 30% 이상이 함께 무너지면 「플랜트를 정지하셨습니까?」 확인 질문을 초안 맨 앞에 넣는 것으로 대응했고, 정지 상황을 하나의 사건으로 묶는 근본 처리는 남은 과제입니다. 이 2종은 포함률 측정에서 제외했습니다.
  2. AI 서술까지 포함하면 5분 목표를 넘깁니다 적재·검출은 5.4초지만 AI 서술·판정을 포함하면 한 근무 13~16항목에 7~10분입니다. 교대 1시간 전 자동 생성에는 충분하지만 목표치(5분)에는 미달 — 5항목 묶음의 순차 호출을 병렬화하면 줄일 수 있으나 실시하지 않았습니다.
  3. 검출 구간이 정답 구간보다 넓습니다 포함률 100%의 이면입니다. 시간축 정밀도 0.46/0.49 — 검출 구간이 정답의 약 2배를 덮습니다. 드리프트 보고 구간을 CUSUM 으로 좁혀 0.40 → 0.46 으로 개선했지만(검출 지연 중앙 −34분 → −0분), 넓게 잡는 성질 자체는 남아 있어 감추지 않고 함께 냅니다.
  4. 근무 경계를 넘는 이상은 그 근무 안에서 결론이 나지 않습니다 근무 끝까지 이어지는 드리프트는 첫 독립 측정에서 「미검출」로 보였습니다. 실제로는 근무가 끝나지 않아 판정할 수 없는 것이라, 다음 근무의 이어받은 항목에서 판정하는 「추적 중」으로 채점 정의를 바로잡았습니다 — 그 근무 안에서 결론을 원하면 이 방식으로는 안 됩니다.
  5. 채택률은 재지 못했습니다 근무자 채택률 50% 목표는 실사용 데이터가 있어야 측정됩니다. 채택·제외를 항목 단위로 기록하는 구조는 구현·검증했지만 값 자체는 미측정 — 파일럿 단계의 몫으로 남깁니다.
  6. 검출이 신호 크기에 단조롭게 반응하지 않습니다 — 원인 미확정 시나리오가 전부 잡음보다 크니 100% 가 당연한 것 아닌가 싶어, 같은 파형의 진폭만 배율로 줄여 다시 쟀습니다(D = 정상 + (주입 − 정상) × 배율, TI-403 저온 이탈). 1배 검출 · 0.3배 놓침 · 0.15배 놓침 · 0.08배 검출 · 0.04배 놓침 — 작을수록 못 잡아야 하는데 그렇지 않습니다. 기준선 오염을 의심해 배율마다 깨끗한 3근무 템플릿을 복사해 다시 쟀지만 결과가 같았습니다. 창 선택 규칙이 크기에 따라 다른 창을 고르는 것으로 보이나 원인은 확정하지 못했습니다. 중간 크기 이상에 사각지대가 있을 수 있다는 뜻이라, 고치지 않은 채로 적습니다.
  7. 근무 후반의 이상은 구간이 근무 전체로 번집니다 위 3번(구간이 넓다)의 가장 나쁜 경우입니다. 외기 보정 계수를 그 근무의 데이터로 적합하기 때문에, 근무 끝에 몰린 이탈이 외기 몫으로 흡수됩니다. 같은 seed 로 시나리오만 뺀 근무와 비교하니 원본 차이는 주입분 +2.60℃ 뿐인데 보정 램프가 +2.17 → +7.81℃ 로 벌어졌고, 그 증가분의 2/3 가 주입이 시작되기도 전 구간에서 생겼습니다. 그 결과 103분짜리 이탈이 12시간 드리프트로 잡혀 IoU 0.14 가 됩니다(60분 창으로는 04:15 에 제대로 잡습니다 — 실제 04:17). 근본 수정은 마감 뒤로 미루고 지표 정의로 드러내는 쪽을 택했습니다.
