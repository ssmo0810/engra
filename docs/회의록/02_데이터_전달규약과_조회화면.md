# 회의 02 — 데이터를 어떻게 주고받을 것인가

| | |
| --- | --- |
| **일시** | 2026-08-16 (일) 18:00 ~ 19:05 |
| **참석** | 박경모 · 정기영 · 임도영 |
| **장소** | 생산팀 사무실 |

## 안건 1 — 전달 규약 (박경모)

생성기와 앱이 각자 바뀌어도 형식이 안 흔들려야 한다.

**결정**
- **형식 `timestamp,tag,value` CSV.** 컬럼 세 개로 고정한다 — 태그가 늘어도 형식이 안 바뀐다
- **주기 2초 · 12시간 1근무 · 태그 53점** → 근무당 **1,144,800행 ≈ 36MB**
- **정답지는 별도 JSON.** 주입 시나리오·영향 태그·시각·알람 실측값
- **전달은 앱 `/pipeline` 업로드.** 파일당 상한 **48MB**, 브라우저에서 gzip 압축

## 안건 2 — 운전원이 데이터를 어떻게 볼 것인가 (임도영)

DCS Overview 만으로는 「지금 값」 밖에 안 보인다. **하루를 한눈에** 볼 화면이 필요하다.

**결정**
- **태그 × 00~24시 시간평균 표.** 가로축 24시간 고정
- **알람 한계를 넘은 칸은 색으로 표시** — 표만 봐도 어디를 볼지 정해진다
- 태그를 누르면 **12시간 트렌드**
- 원시 데이터는 브라우저 메모리에만, **최근 3근무만 보관**(근무 하나 약 9MB)

## 안건 3 — 검출이 요구하는 최소 입력 (정기영)

**결정**
- 초 단위 원본을 그대로 안 쓴다. **30초 블록 중앙값**으로 줄여 받는다
- 태그별 **정상범위와 한계**가 있어야 「알람 전」 을 판정할 수 있다 — 태그 마스터에서 온다
