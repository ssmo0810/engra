## 안건 1 — LLM 을 어떻게 붙일 것인가 (박경모)

처음엔 **CLI 서브프로세스**(비용 0, 외부 의존 0)로 결론냈다가 **뒤집었다.**
그 방식은 초안을 만들 때마다 누군가의 노트북이 켜져 있어야 한다.
ENGRA 의 핵심이 **「교대 1시간 전 초안 자동 생성」** 인데, 그건 정의상 **무인 서버 실행**이다.
제약(비용·의존)을 요구사항보다 위에 둔 착오였다.

**결정**
- **런타임은 서버에서 HTTP API 무인 실행.** 개발·튜닝은 CLI 어댑터로 한다(비용 0)
- **AI 는 필수로 둔다.** 키가 없으면 **초안 생성을 거부하고 이유를 화면에 표시**한다 —
  조용히 문장 틀로 내려가면 「AI 없으면 성립하지 않는다」 는 주장이 거짓이 된다
- **AI 가 맡는 범위** — ① 서술 ② 중요도 판정 ③ 사례 적합성 ④ 의미 단위 묶음

## 안건 2 — AI 가 숫자를 지어내지 못하게 (임도영)

**결정**
- **출력 스키마에 수치 필드를 두지 않는다.** 근거 수치는 **입력으로만** 주고 문장만 만들게 한다.
  지어낼 자리 자체를 없앤다
- `tag` · `severity` · `evidence` · `precedents` 는 **원본 그대로 통과**
- **조치를 지어내지 않는다.** 현장 조치는 **과거 확정 일지에 있는 것만** 유효하다 —
  모델은 이 공장의 절차를 모른다. AI 가 할 일은 그 사례가 이번 현상에 맞는지 **판정**하는 것
- 프롬프트로 지시한 것과 모델이 스스로 판단한 것을 **구분해 기획서에 적는다**

## 안건 3 — 엔진 쪽에 바뀌는 것 (정기영)

**결정**
- **없다.** LLM 은 `app/ports.py` 층에서 감싼다. `engine/` 은 안 건드린다
- 대신 **`metrics` 에 숫자를 풍부하게** 담아 준다 — 스키마에서 수치를 뺐으므로
  근거는 전부 `metrics` 에서 나온다
