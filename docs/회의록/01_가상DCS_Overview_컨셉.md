## 논의
- 실제 설비 태그 체계와 운전 수치는 쓸 수 없다(대회 보안 가이드). **가상 ASU 공정을 새로 만든다.**
- 화면이 현장 DCS Overview 를 닮아야 근무자가 설명 없이 읽는다. 미믹 · 배관 · 컨트롤 밸브 · 계측 태그.
- 태그를 몇 점 둘까 — 너무 적으면 공정이 설명되지 않고, 너무 많으면 12시간 데이터가 감당이 안 된다.
- 명명 규칙을 먼저 정하지 않으면 나중에 화면·문서·엔진이 서로 다른 이름을 쓴다.

## 결정
- **태그 53점.** 한 ASU 공정을 설명할 최소 규모로 잡는다.
- **명명 규칙** — 접두 알파벳 + 3자리 번호, **앞자리가 설비 구분**.
  `T` 온도 · `P` 압력 · `PD` 차압 · `F` 유량 · `L` 레벨 · `A` 분석 · `M` 수분 · `Z` 밸브개도 · `S` 회전수 · `J` 전력
- **유닛 9개** — AIR FILTER `F-101` / AIR COMPRESSOR `K-201` / ADSORBER `A-301·302` /
  MAIN HX `E-401` / TURBINE `X-501` / COLD BOX INLET `FV-601` / COLUMNS `C-701·702` /
  PRODUCT TANKS `TK-801·802` / GN2 SUPPLY
- **태그 마스터 CSV 를 단일 출처로 둔다** — 정상값 · 정상범위 · LL·L·H·HH · 드리프트 · 노이즈 · 연동.
  화면·문서·엔진이 모두 이 파일을 인용한다.
- 화면의 모든 값은 가상 데이터임을 표기한다.
