# 제작 과정 — 자동 생성 문서

**이 폴더의 파일은 손으로 쓰지 않습니다.** 커밋 기록과 GitHub Issue 에서 자동으로 만듭니다.

```bash
python3 tools/journal.py
```

## 왜 이렇게 하나

본선 제출 폴더 「04. 제작 과정」은 **15점**(문제해결 과정의 집요함)이고,
평가 기준에 이렇게 적혀 있습니다.

> 결과물만으로는 드러나지 않는 부분이라 별도로 기록해 주셔야 확인할 수 있습니다.

FAQ 에도 *"검증 기록과 제작 과정은 나중에 되살리기 어렵습니다"* 라며 그때그때 쌓아두라고
나옵니다. 그래서 **따로 일지를 쓰는 방식을 쓰지 않습니다.** 어차피 남기는 것에서 뽑아냅니다.

| 문서 | 원본 | 무엇이 들어가나 |
| --- | --- | --- |
| `개발일지.md` | 커밋 기록 | 날짜별 변경 내역 · 작성자 · 왜 바꿨는지 |
| `회의록_결정기록.md` | GitHub Issue | 무엇을 정해야 했는지 · 논의 · 결론 · 처리 시각 |
| `난관과_극복사례.md` | 커밋 본문 | 문제를 만나 넘은 기록 (발견·결함·재현 등의 서술로 수집) |
| `사용도구.md` | `Co-Authored-By` | 사용한 도구와 참여 비중 (FAQ Q5 요구사항) |

## 그래서 팀이 할 일

**따로 없습니다.** 평소대로 하면 쌓입니다. 단 세 가지만 지키면 됩니다.

1. **커밋 본문에 왜 바꿨는지와 무엇으로 확인했는지 적기** → 개발 일지가 됩니다
2. **문제를 만나 고쳤으면 그 사실을 적기** → 난관과 극복 사례가 됩니다
   조용히 고치면 15점짜리 항목에서 사라집니다
3. **회의하거나 정할 일이 생기면 이슈로 남기기** → 회의록이 됩니다

제출 직전에 `python3 tools/journal.py` 를 한 번 돌려 최신 상태로 만들고,
Drive 의 「04. 제작 과정」 폴더에 올립니다.
