- Playground 이용 시 관련 규정 및 이용조건 등의 의무를 준수하고, 신의에 따라 성실하게 이용합니다.
- AI 해커톤을 통해 취득한 타 참가자의 아이디어, 결과물 등을 무단으로 복제·유출·상업적 활용하지 않아야 합니다.
- AI 해커톤 기간 중은 물론, 종료 후에도 업무상 알게 된 제반 사항을 일체 누설하지 않아야 합니다.
## 2. 업로드 금지 데이터
- 사내 기밀 자료: 영업비밀, 미공개 경영정보, 기술 사양서, 내부 전략 문서 등
- 개인정보: 고객·임직원의 성명, 연락처, 이메일, 사번, 주민등록번호 등 개인을 식별할 수 있는 일체의 정보
- 비공개 데이터: 사내 시스템에서 추출한 원본(Raw) 데이터, 데이터베이스 덤프, 로그 파일 등
- 고객 데이터: 고객사 계약 정보, 거래 내역, 서비스 이용 기록 등
## 3. 데이터 업로드 시 조치 필요 사항
- 사례 소개 시 사내 데이터를 활용한 내용이 포함되는 경우, 반드시 비식별 처리(마스킹, 가명 처리 등)를 완료한 후 업로드해야 합니다.
- 스크린샷·이미지에 사내 시스템 화면이 포함되는 경우, 민감 정보(이름, 금액, 식별번호 등)를 모자이크 또는 블러 처리한 후 업로드해야 합니다.
- 확인이 어려운 경우, 소속 멤버사의 정보보호 담당 부서에 사전 확인을 받을 것을 권장합니다.
## 4. 위반 시 조치
- 위반 사실 적발 즉시 해당 제출물 삭제 및 참가 자격 박탈(실격)

    C -->|"그렇다"| E{"비식별 처리 후에도<br/>누구인지 알 수 있나?"}

- 데모에 필요한 건 "진짜 값"이 아니라 "진짜 같은 구조"입니다. 컬럼 이름과 데이터 형태는 유지하고 값만 생성하면, 작동도 하고 보안도 지킵니다. 
  사내 원본 데이터는 올리실 수 없습니다. 비식별 처리한 데이터나 같은 구조로 만든 모사 데이터로 대체하시고, 그렇게 했다는 사실과 방식을 「03. 데이터 세트」의 검증 결과 정리에 적어주시면 동일하게 평가합니다.
  평가에서 보는 「실제 업무 데이터」는 원본을 올리라는 뜻이 아니라, 실제 업무에서 쓰는 데이터와 유사한 구조·같은 난이도의 데이터로 확인하셨는지를 뜻합니다.
## 올리면 안 되는 것
| 예시 | 유형 |
| 영업비밀, 미공개 경영정보, 기술 사양서, 내부 전략 문서 | 사내 기밀 자료 |
| 고객·임직원의 성명, 연락처, 이메일, 사번, 주민등록번호 | 개인정보 |
| 사내 시스템 raw 데이터, DB 덤프, 로그 파일 | 비공개 데이터 |
| 고객사 계약 정보, 거래 내역, 서비스 이용 기록 | 고객 데이터 |
- API 키, 비밀번호, 접속 토큰, 사내 시스템 주소도 어디에도 남기지 마세요. 
- 코드에 하드코딩하지 말고 환경변수로 분리하고, 그 파일은 제출물에서 제외해주세요.
  위 「개인정보」는 제3자(고객·타 임직원)의 정보를 자료나 데이터로 올리는 경우를 말합니다. 작성자 본인과 팀원의 이름·소속·역할은 해당하지 않으며, 오히려 제출물에 명확히 밝혀주셔야 합니다.
  기획서와 개발 일지에 누가 어떤 부분을 맡았는지 남겨주세요. 제작 과정은 평가 대상이고, 시상과 문의 응대도 팀·구성원 확인을 거쳐 진행됩니다.
- 본인·팀원의 정보로 밝혀주셔야 하는 범위는 이름·소속·역할까지입니다.
- 화면에 사용자 정보가 보여야 한다면 홍길동 / demo01@example.com / 010-0000-0000처럼 형태만 같은 가상 데이터로 채워주세요.
## Claude를 쓸 때 특히 조심할 것
문제가 발생하는 지점은 "데이터 파일을 올리는 순간"이 아니라 아래 다섯 가지입니다. 의식하지 못한 채 나가기 때문입니다.
1. Claude Code를 아무 폴더에서나 실행하는 것
Claude Code는 실행한 위치의 파일을 읽습니다. 사내 문서가 섞여 있는 폴더나 바탕화면에서 실행하면, 요청하지 않은 파일까지 읽힐 수 있습니다. 해커톤 전용 폴더를 새로 만들고 거기서만 실행하세요.
2. 에러 메시지·로그를 통째로 붙여넣는 것
가장 놓치기 쉬운 경로입니다. 스택 트레이스와 로그에는 내부 서버 주소, DB 스키마, 테이블·컬럼명, 파일 경로, 때로는 사번까지 들어 있습니다. 붙여넣기 전에 어디까지 찍혀 있는지 한 번 읽어보세요.
3. 사내 화면 스크린샷
화면 본문만 보고 캡처하지만, 상단 주소창·계정명·사번·조직도가 함께 찍힙니다. 필요한 영역만 잘라내고 나머지는 가리세요.
4. 만든 앱을 그냥 배포하는 것
배포한 URL은 인터넷에 열립니다. 제출용 앱에 실제 데이터를 넣어두면 링크를 아는 누구나 볼 수 있습니다. 배포용 앱에는 가상 데이터만 넣으세요. 실제 데이터가 필요하면 로그인을 걸고, 접속 방법을 제출 폴더에 적어주세요.
5. "요약해줘"도 반출입니다
원본을 요약·번역·분석시키는 것도 원본을 전송한 뒤에 일어나는 일입니다. 결과물이 요약본이라고 해서 입력이 없던 일이 되지 않습니다.
## 비식별 처리, 이렇게 하세요
효과가 큰 순서입니다.
- 삭제 — 그 컬럼이 없어도 되면 지웁니다. 가장 안전합니다.
- 대체 — 김O수 같은 부분 가림이 아니라 사용자A, 고객001처럼 통째로 바꿉니다.
- 범주화 — 1985-03-12 → 30대, 12,847,300원 → 1천만원대.
마스킹은 "가렸다"가 아니라 "복원 불가능하다"까지 가야 합니다
## 판단이 어려우면
비식별이나 모사 처리를 하셨다면, 그 사실과 방식을 「03. 데이터 세트」에 함께 적어주세요. 적어주시면 원본을 쓴 것과 동일하게 평가합니다. 적지 않으시면 심사위원이 어떤 데이터로 검증하신 것인지 알 수 없어, 재현 가능성을 확인할 수 없습니다.
## 위반 시
제출물 삭제, 참가 자격 박탈, 수상 취소, 상금 환수, 징계 및 법적 책임까지 이어질 수 있습니다. 참가자는 해커톤 기간 중과 종료 후에도 업무상 알게 된 내용을 누설해서는 안 됩니다.
실격 판정에 대해서는 소명을 신청할 수 있습니다. 내부 심의를 거쳐 최종 실격 여부가 결정됩니다.

## 자주 막히는 경우
- Settings 탭이 보이지 않습니다.
  저장소 소유자 또는 관리자 권한이 있는 계정으로 로그인했는지 확인해 주세요. 권한이 없으면 공동 작업자를 초대할 수 없습니다.
- Read 권한 선택 화면이 보이지 않습니다.

- 초대 후 Pending 상태로 보입니다.
  초대 발송 자체가 완료된 상태입니다. 초대 화면이 Pending으로 보이는 경우에도 저장소 주소를 함께 제출해 주세요.
