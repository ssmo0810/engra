## 1. 판정 기준 — 무엇을 탐지로, 무엇을 오탐으로 세는가

**측정 도구는 `tools/score.py` 하나로 통일한다.** 판정 기준은
`docs/scenarios.md` 「전파 경로와 기대 탐지 결과」를 따른다.

| | 정의 |
| --- | --- |
| **탐지** | 주입 구간과 **시간이 겹치는** 이벤트가, 정답지의 `affected_tags` 또는 `trigger_tag` **중 하나**에서 나옴 |
| **오탐** | 어느 주입 구간·영향 태그와도 겹치지 않는 이벤트 |
| **동시 발생** | 겹친 구간은 두 시나리오 어느 쪽에 붙어도 탐지로 인정 (정답지 `note`) |
| **집계 단위** | 이벤트 단위. 한 사건이 검출기 넷에 걸리면 탐지는 1, 오탐은 각각 센다 |

> 주의 — `engine/selftest.py` 의 수치는 **검출기를 만든 사람이 만든 픽스처로 잰
> 예비치**다. 제출·판정에는 쓰지 않는다. 두 숫자를 섞지 않는다.

## 2. 품질 기준 (합격선)

`data/sim/asu_answer_all.json` (6근무 · 48건 주입) 기준.

| 지표 | 합격선 | 근거 | 현재 |
| --- | --- | --- | --- |
| 주입 건 포함률 | **≥ 90%** | `engine/README.md` 기존 목표. 20종 중 18종 = 알람 미발생 13종 전부 + 알람 발생 7종 중 5종 | **98%** (47/48) ✅ |
| 시나리오 종 커버 | **≥ 18/20 종** | 위와 같은 근거 | **20/20** ✅ |
| **근무당 오탐** | **≤ 3.0건** | 아래 산출 근거 | **2.2건** ✅ |
| **오탐률 (오탐/전체 이벤트)** | **≤ 10%** | 아래 산출 근거 | **7.5%** (13/174) ✅ |
| 알람 발생 종의 선행 검출 | **≥ 70%** | 알람보다 먼저 잡지 못하면 ENGRA 의 가치가 없다 | **75%** (12/16) ✅ |
| 근무자 채택률 | ≥ 50% | `engine/README.md` 기존 목표 | 미측정 — 승인 화면 누적 필요 |

### 오탐 기준을 3.0건으로 정한 근거

한 근무 초안은 **10~13개 항목**으로 묶인다(실측: 11·13·11·12·10·12).
근무자가 교대 시각에 검토하는 단위가 이것이다.

1. **오탐이 항목의 1/4을 넘으면 신뢰를 잃는다.** 11.5개 항목 × 25% ≈ 2.9건 →
   **3.0건**으로 잡았다. 넷 중 하나가 헛것이면 근무자는 초안 전체를 안 믿는다.
2. **채택률 50% 목표와 정합한다.** 오탐이 3건을 넘으면 나머지가 전부 옳아도
   채택률 상한이 내려간다.
3. 이벤트는 근무당 약 29건이 나오고 그것이 10~13항목으로 묶이므로, 이벤트
   기준 10%(≈2.9건)와 항목 기준 25%가 같은 수치로 만난다.

> **오탐 예산이 있어야 문턱 조정이 가능해진다.** 포함률만 보면 문턱을 계속
> 내리는 것이 항상 이득이므로, 반대쪽 제약이 없으면 조정 규칙이 성립하지 않는다.

## 3. 전처리 — 모든 검출기의 공통 입력

### 3-1. 블록 접기

원본 2초 주기 × 12시간 × 53태그 = **114만 점**. 원본에 이동창 통계를 돌리면
이동 횟수가 1억을 넘어 초안 생성 시간 안에 끝나지 않는다.

```
블록 길이 BLOCK_SEC = 30초  →  근무당 1,440블록 (1/15 로 축약)
블록마다 보관: med(중앙값) · mad · lo(원본 최소) · hi(원본 최대)
```

**`lo`·`hi` 를 반드시 함께 남긴다.** `med`·`mad` 만 남기면 3초짜리 분석기
폭등(시나리오 12)과 10초짜리 유량 급강하(시나리오 5)가 평균에 묻혀 사라진다.

**스파이크는 통계에서만 뺀다.** 999ppm 한 점이 `median`/`MAD` 에 들어가면 그
태그 기준선이 부풀어 다른 시나리오 탐지까지 죽는다. 다만 **탐지에서는 남긴다**
— 기준선에서 빼는 것과 근무자에게 알리는 것은 다른 문제다 (Issue #2).

### 3-2. 산포 추정

```
MAD_TO_SIGMA = 1.4826
σ = MAD × 1.4826                      평균·표준편차를 쓰지 않는다 (이상에 끌려간다)

q  = quantum      기록된 값의 최소 눈금 (인접한 서로 다른 값들의 최소 간격)
raw_noise = median(블록 mad) × 1.4826
s_noise   = max(raw_noise, q × 0.5, span × 1e-4)
s_level   = max(σ(직선추세 제거한 블록 med), q, span × 1e-4)
```

**`q` 를 바닥으로 깔지 않으면 검출기가 통째로 망가진다.** 정상범위 폭이 0.07 인
차압 태그가 소수 2자리로 기록되면 눈금(0.01)이 실제 노이즈(0.001)보다 열 배
크다. 그러면 블록 MAD 가 0 이 되고 **한 눈금 이동이 1,429σ 로 계산된다.**

**`s_level` 은 직선 추세를 제거한 뒤에 잰다.** 근무 내내 이어지는 드리프트는
자기 자신을 '평소 산포' 로 만들어 버린다. 12시간에 8.2℃ 오른 태그의 원본 MAD 는
3.0℃ 라 변화가 겨우 2.7배로 계산돼 탐지에서 빠졌다. 추세를 빼면 7.8배가 된다.

### 3-3. 외기(잡음인자) 보정 — **드리프트 검출 전용**

```
NOISE_TAGS = ("TI-101", "MI-102")        ← 선언. tag_master 의 noise_factor 열로 옮길 것
```

**절차**

1. 잡음인자 태그의 블록 med 를 표준화해 기준자로 만든다 — `(x − median) / σ`
2. **기준자끼리 겹치는 몫을 그람-슈미트로 제거**한다. 남은 크기(RMS)가 `0.1`
   미만이면 새 정보가 없는 것으로 보고 버린다.
   → 실측에서 `TI-101 ↔ MI-102` 상관이 **−0.9998** 이라 습도 기준자가 버려진다.
     생성기가 온도·습도를 같은 일주기 함수 하나로 만들기 때문이다.
3. 대상 태그와 기준자 **양쪽에서 직선(기울기+절편) 성분을 지운다** → 곡률만 남음
4. **곡률끼리** 최소제곱으로 맞춰 계수 `a` 를 구한다
5. 3σ 밖 블록을 빼고 **한 번 다시 맞춘다** (주입된 이상이 계수를 정하면 안 된다)
6. 그 `a` 로 **직선 성분까지 포함한 외기 원본 전체**를 뺀다 → `adj`
7. 아래 두 관문을 통과할 때만 적용

```
관문 ①  |상관(대상 곡률, 적합값)|  ≥ NOISE_MIN_R     = 0.20
관문 ②  (max(외기몫) − min(외기몫)) ≥ NOISE_MIN_SWING × s_level  = 1.0배
s_adj = max(σ(직선추세 제거한 adj), q, span × 1e-4)
```

**왜 3~4단계로 나누는가.** 12시간 창에서 외기 반주기는 거의 단조라
**「직선」과 「외기」가 구분되지 않는다.** 시간항을 함께 넣으면 몫 배분이
결정되지 않고, 빼면 외기가 고장 램프를 삼킨다. **외기에는 곡률이 있고 고장
램프에는 없다** — 이것이 유일한 단서다.

**관문 두 개의 판별력** (실측)

| | 외기 감응 태그 | 무관한 태그 |
| --- | --- | --- |
| 곡률 상관 | 0.30 ~ 0.79 | 0.01 ~ 0.09 |
| swing / σ | 2.4 ~ 6.4배 | 0.07 ~ 0.62배 |

두 관문이 **태그 마스터를 보지 않고도** 감응 태그를 데이터만으로 골라낸다
(주간 53개 중 23개 발동). 외기 태그가 없는 데이터셋이면 보정을 건너뛰고
기존대로 돈다 — **다른 공장 데이터가 들어와도 깨지지 않는다.**

## 4. 검출기 7종 — 수식과 확정 문턱값

기호: `med[i]` 블록 중앙값 · `mad[i]` 블록 MAD · `lo/hi` 블록 원본 최소/최대

### ① 알람 한계선 교차 `limit_crossings`

```
조건   상한: hi[i] > H (또는 HH)        하한: lo[i] < L (또는 LL)
최소 지속   1블록 (30초)
중요도      HH·LL = 상,  H·L = 중
```

같은 방향에서 **더 심한 것 하나만** 남긴다(HH 가 잡히면 H 는 생략).
ENGRA 의 가치는 아니지만 **알람이 울린 건도 인계장에 들어가야 한다.**

### ② 드리프트 `drift` — **`adj`·`s_adj` 사용**

```
창 길이   drift_windows_min = (60, 120, 240, 720) 분     시작점 간격 = 창/4
기울기·상관   slope, r = OLS(adj[i : i+w])
Δ = slope × (w − 1)
k = |Δ| / s_adj

채택 조건   k ≥ drift_k = 3.5   AND   |r| ≥ drift_r = 0.60
```

**30분 창은 뺐다.** 정상 데이터의 진동 주기가 20~60분이라 30분 창은 그 반주기를
통째로 담아 단조 상승처럼 보인다. 실측에서 오탐 7건이 전부 30분 창에서 나왔다.
60분부터는 진동이 되돌아와 `|r|` 이 떨어진다.

**여러 창이 걸리면 가장 강한 것이 아니라 「가장 먼저 나타난 창」을 고른다**
(세기가 최대의 60% 이상인 것 중 최소 `i`). 이상이 끝나고 되돌아오는 구간이
대개 더 가파르기 때문에, 최대치만 보면 **상승 추세를 하강 추세로 보고한다.**

```
한계 도달 예상   eta = (limit − med[j−1]) / (시간당 기울기)      0 < eta < 48시간일 때만 표기
중요도           eta ≤ 12시간이면 '상', 아니면 k 로 판정 (≥10 상 / ≥5 중 / 그 외 하)
외기 몫 표기     |외기몫 변화| > |실측 변화| × 0.15 일 때 초안에 분해를 적는다
```

### ③ 레벨 시프트 `level_shift`

```
변화점 후보   c ∈ [w, n−w),  간격 w/4        w = step_min_blocks = 20블록(10분)
a = median(med[c−4w : c])      b = median(med[c : c+4w])
k = |b − a| / s_level

채택 조건   k ≥ step_k = 3.0     (전 구간에서 k 가 최대인 c 하나만)
```

**CUSUM 을 쓰지 않는다.** 정상 데이터의 느린 진동에 CUSUM 은 반주기마다 걸린다 —
진폭 1.4σ 가 15분 지속되면 누적합이 문턱을 넘는다. 앞뒤 중앙값 차이는 진동에
반응하지 않는다. (`engine/README.md` 의 「CUSUM 기준(k,h)」 항목은 **미채택**으로
확정한다.)

### ④ 헌팅 `hunting`

```
ratio[i] = (mad[i] × 1.4826) / s_noise
에피소드 = ratio ≥ hunt_ratio(3.0) 이 hunt_min_blocks(2블록=60초) 이상 연속
진폭 = max(hi) − min(lo)   (최대 에피소드 구간에서)

악화 판정   에피소드 3개 이상 AND 마지막 peak > 첫 peak × 1.3   → '상'
중요도      악화 중이거나 top ≥ 10 이면 '상', 아니면 ≥8 상 / ≥4 중 / 그 외 하
```

`hunt_min_blocks` 를 2 아래로 내릴 수 없다 — 시나리오 3 의 1회 지속이 60초다.
**값이 아니라 변동폭을 보므로** 블록보다 짧은 주기(시나리오 3 은 20초, 13 은
45초)도 블록 안 산포로 드러난다.

### ⑤ 순간 이탈 `spike`

```
scale = max(median(|med[i+1] − med[i]|) × 1.4826,  s_noise)
c[i]  = (med[i−1] + med[i+1]) / 2                    ← 앞뒤 블록의 중간값
z[i]  = max(|hi[i] − c[i]|, |c[i] − lo[i]|) / scale

채택 조건   z ≥ spike_z = 8.0   AND   지속 ≤ spike_max_blocks = 4블록(2분)
```

**비교 대상이 앞뒤 중간값인 것이 핵심.** 처음에는 「±5블록 국소 중앙값 / 노이즈
σ」로 잡았다가 바꿨다 — 변동이 빠른 태그(`drift_level 3`)는 5분이면 정상적으로
크게 움직이는데 그 이동을 노이즈 σ 로 나누니 15σ 가 나와 **근무당 오탐이 열 건
넘게 쌓였다.** 앞뒤 중간값과 비교하면 완만한 이동은 상쇄되고 튀는 점만 남는다.

2분을 넘으면 스파이크가 아니라 다른 현상이므로 다른 검출기 몫으로 넘긴다.

### ⑥ 임계 근접 `near_limit`

```
ref  = 정상범위 상·하한과 알람선 중 nominal 에서 더 가까운 쪽
frac[i] = (med[i] − nominal) / (ref − nominal)

채택 조건   frac ≥ prox_frac(0.85) 이 prox_min_blocks(60블록=30분) 이상 연속
            AND  median(구간 frac) ≥ 0.85        ← 진동 꼭짓점이 스친 것 배제
중요도      top ≥ 0.95 면 '중', 아니면 '하'
```

**한계를 「먼저 닿는 선」으로 잡는 것이 요점.** 시나리오 4 는 정상 상한(20℃)이,
시나리오 10 은 알람선(H 88%)이 기준인데 둘 다 먼저 닿는 선이다.

### ⑦ 고착 `stuck`

```
전제   view.resolves() — 실제 노이즈가 기록 눈금보다 커야 판정 가능
       (눈금이 노이즈를 삼킨 태그는 값이 멈춰 있는 것이 정상이다)
cut = max(q,  raw_noise × stuck_frac(0.05))
조건   (max(med[i:i+w]) − min(med[i:i+w])) ≤ cut  AND  max(mad[i:i+w]) ≤ cut
       w = stuck_min_blocks = 40블록(20분)
중요도  항상 '상'
```

**조용한 것과 죽은 것은 다르다.** 이걸 못 잡으면 "이상 없음" 으로 인계된다.

### ⑧ 상관 이탈 `residual` — 태그 쌍

```
전제   tag_master 의 links 에 선언된 쌍만.  지연 lag = links 의 지연초 / 30
       |pearson(지연반영 src, tgt)| ≥ resid_min_r = 0.50
              ← 평소에도 안 붙어 있는 쌍은 붕괴를 논할 수 없다

b   = Σ(x−x̃)(y−ỹ) / Σ(x−x̃)²
err[i] = |(y[i] − ỹ) − b·(x[i] − x̃)|            ← 절댓값. 평균을 쓰면 ± 가 상쇄된다
roll  = err 의 40블록(20분) 이동평균
z     = (roll − median(err)) / (MAD(err) × 1.4826)

채택 조건   z ≥ resid_z = 3.0 이 resid_min_blocks = 40블록(20분) 이상 연속
중요도      항상 '상'
```

**잔차의 평균이 아니라 절댓값의 평균**을 쓴다. 한쪽이 멈추고 다른 쪽이 진동하면
잔차가 ± 로 오가면서 평균이 0 이 되어 버린다.

## 5. 사건 묶기

이벤트를 그대로 내보내지 않는다. **근무자가 읽는 단위는 사건이지 태그가 아니다.**

```
같은 사건 조건   시간이 겹친다  AND  tag_master 의 links 로 이어진다
                 (직접 연결 + 공통 이웃 1홉까지 인정)
```

**태그 번호 첫 자리로 계통을 묶으면 안 된다.** `8xx` 안에 LOX 탱크와 LIN 탱크가
같이 들어 있어, 밸브 고착과 무관한 다른 탱크 알람이 초안 한 줄에 섞여 나갔다.

## 6. 문턱 조정 규칙

두 지표가 **서로 반대 방향**으로 당기므로 둘을 함께 본다.

| 증상 | 조정 |
| --- | --- |
| 포함률 < 90% | 해당 검출기의 `k`·`z`·`ratio` 를 **내린다** |
| 근무당 오탐 > 3.0건 | 해당 검출기의 문턱을 **올린다.** 단 먼저 오탐을 검출기별·태그별로 갈라 볼 것 |
| 채택률 < 50% | 문턱을 올린다 (근무자가 안 쓰는 항목이 많다는 뜻) |
| 특정 태그에 오탐 집중 | **문턱이 아니라 태그 마스터를 의심한다** — 아래 참고 |

**오탐을 갈라 보지 않고 문턱부터 올리면 안 된다.** 실측에서 오탐 67건 중 54건이
드리프트였고 그 54건이 전부 외기 감응 태그였다. 문턱을 올렸다면 오탐과 함께
진짜 탐지도 같이 잃었을 것이다. **원인이 하나면 문턱이 아니라 구조를 고친다.**

## 7. 검증 명령어

```bash
# 1) 회귀 확인 — 자체 픽스처 (예비치, 제출용 아님)
python engine/selftest.py

# 2) 독립 데이터 적재 + 검출 (근무 하나)
python app/cli.py ingest data/sim/asu_2026-08-22-day_12h.csv
python app/cli.py run --redo 2026-08-22-day

# 3) 6근무 전체 (반복)
for f in data/sim/asu_*.csv; do
  sid=$(basename "$f" | sed 's/^asu_//; s/_12h\.csv$//')
  python app/cli.py ingest "$f"
  python app/cli.py run --redo "$sid"
done

# 4) 정답지 대조 — 이 숫자가 판정 기준이다
python tools/score.py data/sim/asu_answer_all.json
```

`app/cli.py init` 첫 줄과 화면 오른쪽 위에 `engine` / `stub` 이 표시된다.
`engine` 이 아니면 `engine/api.py` 로딩이 실패한 것이므로 먼저 그것부터 본다.

**문턱을 바꿀 때는 `engine/detectors.py` 의 `PARAMS` 한 곳만 고친다.**
외기 보정 상수는 `engine/core.py` 의 `NOISE_*` 세 개다.
