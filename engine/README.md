# 감지 엔진 설계

운전 데이터에서 특이사항 후보를 찾아내는 통계 기반 검출 로직을 정의합니다.
여기서 정한 방식이 프로토타입 구현의 사양이 됩니다.

- 담당: 정기영
- 입력: 근무 구간(12시간) 태그별 시계열, 태그별 베이스라인
- 출력: 이벤트 목록 (구간 · 유형 · 지표 · 중요도)

---

## 설계 원칙

**고정 임계값이 아니라 태그별 베이스라인 대비로 판정합니다.**
관리 기준 5%에 미달하는 3% 진동이라도, 그 태그의 평소 변동폭이 0.3%라면 이례적인 변화입니다.
알람에 걸리지 않는 신호를 잡는 것이 이 서비스의 핵심 가치이므로, 절대 기준만으로는 목적을 달성할 수 없습니다.

**학습 기반 모델이 아니라 통계 기반으로 갑니다.** 이유는 셋입니다.
정상·이상이 라벨링된 과거 데이터가 없어 학습이 성립하지 않고,
근무자가 "이게 왜 올라왔나"를 확인할 수 없으면 초안을 신뢰하지 않으며,
동일 입력에 동일 결과가 나오는 재현성이 개발 목표에 포함되어 있습니다.

**통계 단계는 재현율을 우선합니다.** 문턱을 낮게 잡아 넓게 통과시키고,
정밀도는 뒤따르는 중요도 판정과 근무자의 선택이 담당합니다.
놓친 신호는 복구할 방법이 없지만, 오탐은 근무자가 체크박스로 걸러내면 됩니다.

---

## 기준값 산출

평균·표준편차 대신 **중앙값과 중앙값 절대편차(MAD)** 를 씁니다.
운전 데이터는 소수의 극단값에 평균·표준편차가 크게 흔들리는 반면, 중앙값 기반 지표는 그 영향을 받지 않습니다.

- 근무가 끝날 때마다 태그별 통계 1행을 산출해 누적
- 누적분으로 태그 × 시간대별 기준값(중앙값, MAD)을 갱신
- **승인된 특이 구간은 기준 계산에서 제외** — 정지·사고 구간이 섞이면 MAD가 부풀어 다음부터 같은 이상을 못 잡습니다

이탈도 판정: `0.6745 × (값 − 중앙값) ÷ MAD`

## 증상별 검출기

| 증상 | 방법 | 이유 |
| --- | --- | --- |
| 값 이탈 | 수정 z-score | 기본 판정 |
| 헌팅(진동) | 이동창 표준편차 ÷ 베이스라인 표준편차 | 진동은 값이 아니라 변동폭이 커지는 현상이라 이탈도만으로는 안 잡힘 |
| 드리프트 | 이동창 회귀 기울기 | 기울기 × 남은 시간 = 임계 도달 예상 시각까지 산출됨 |
| 레벨 시프트 | CUSUM 또는 EWMA 관리도 | 작지만 지속적인 변화 감지에 특화, 공정관리 표준 도구라 현장 수용성도 높음 |
| 임계 근접 | 관리 한계 인근 체류 시간 누적 | 알람은 없었지만 위험했던 구간 |
| 상관 이상 | 평소 동조하던 태그 쌍의 상관 붕괴 | 단일 태그로는 안 보이는 이상 (여유 시) |

## 후보 통합과 중요도

1. 검출기별 후보 구간을 시간축에서 병합 (겹치면 하나의 사건으로)
2. 중요도 = 이탈 크기 × 지속 시간 × 임계 근접도 × 연속 발생 가중
3. 중요도 순으로 정렬하되 **걸러내지 않고 전부 표시**
4. 각 항목에 원천 데이터(태그·시각·수치)를 연결

## 채워야 할 것

아래는 실제 구현 전에 정해야 하는 값입니다. 초기값을 잡고 측정하며 조정합니다.

| 항목 | 초기값 후보 | 확정 |
| --- | --- | --- |
| 이탈도 문턱 | 수정 z-score 3.5 | |
| 헌팅 판정 비율 | 베이스라인 대비 3배 | |
| 헌팅 이동창 길이 | 10분 | |
| 드리프트 최소 지속 | 60분 | |
| 드리프트 최소 기울기 | 유의성 검정 기준 | |
| CUSUM 기준(k, h) | | |
| 임계 근접 정의 | 상한의 95% | |
| 임계 근접 최소 체류 | 30분 | |
| 베이스라인 산출 창 | 최근 근무 N회 | |

측정 목표: 주입 시나리오 대비 **포함률 90% 이상**, 근무자 **채택률 50% 이상**.
두 수치가 조정의 기준이며, 채택률이 낮으면 문턱을 올리고 포함률이 낮으면 내립니다.
