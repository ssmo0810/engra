## 돌리는 순서 — 중요

**근무별로 `ingest → run → approve` 를 반복해야 합니다.**

```bash
python3 app/cli.py init

for f in data/sim/asu_2026-08-2*_12h.csv; do
  python3 app/cli.py ingest "$f"     # 출력되는 근무 ID 확인
  python3 app/cli.py run <근무ID>
  # 승인 화면에서 채택·코멘트 후 확정
done
```

셋을 다 `ingest` 한 뒤 몰아서 `run` 하면 **과거 조치가 회수되지 않습니다.** 사례 검색이 초안 생성(`compose`) 시점에 일어나므로, 앞 근무가 확정된 뒤에 다음 근무를 `run` 해야 합니다. (`HANDOFF.md` 경고와 같은 내용입니다.)

## 재현

`base_seed 20260830` · `base_start 2026-08-22T06:00:00` 입니다. 생성기에 같은 값을 넣고 6번 누르면 **동일한 파일**이 나옵니다.

랜덤 모드지만 seed 가 고정이라 선택·배치가 모두 재현됩니다. 20/20 커버리지가 나오는 seed 를 골랐고, 그 값이 답안지에 기록돼 있습니다.

## 답안지 읽는 법

`asu_answer_all.json` 의 `shift_list[].injected[]` 가 근무별 정답입니다.

| 필드 | 뜻 |
| --- | --- |
| `dcs_alarm` | **선언값이 아니라 생성된 데이터에서 실측한 값**입니다 |
| `carried_in` | 앞 근무에서 이어진 이상 |
| `continues_next` | 다음 근무로 이어지는 이상 |
| `duration_sec` | 이 근무 안에 담긴 길이 (`#14` 처럼 20초짜리는 분 단위로 0 이 됩니다) |
| `overlaps` | 같은 태그에서 겹친 조합 |

**동시 발생 구간에서는** 한 시나리오의 `dcs_alarm` 이 겹친 다른 시나리오 때문일 수 있습니다. 채점하실 때 `overlaps` 를 함께 보십시오.
