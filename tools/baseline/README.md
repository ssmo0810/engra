# 사람 기준치 측정 (파일럿)

같은 12시간 근무 데이터를 **사람이 추이 화면으로 훑어 인계할 변화를 찾는 경우**와 **ENGRA 가 돌리는 경우**를
같은 채점 규칙으로 잰다. 가상 데이터만 쓴다 — 사내 데이터·실운영 데이터는 쓰지 않는다.

필요한 것: Node(생성, v20 에서 확인) · Python 3.10 이상(채점) · Chrome(시험). 설치할 패키지는 없다.

## 준비물

| 파일 | 하는 일 |
| --- | --- |
| `make_shift.js` | 생성기(`docs/asu_dcs_overview.html`)를 원본 그대로 헤드리스로 돌려 새 seed 근무 1개와 봉인 정답지를 만든다. 화면에 정답을 그리는 함수만 비운다. |
| `viewer.html` | 시험자용 추이 화면. 태그 53개 미니 추이 + 상세(끌어서 확대) + 한계선. 검출 결과·이상 표시·정렬은 없다. 발견 기록과 경과 시간을 JSON 으로 내보낸다. |
| `compare.py` | 봉인·기록지 확인 → ENGRA 실행(새 DB) → 사람 기록과 함께 `tools/score.py` 의 `score_shifts` 로 채점. |

## 역할

- **진행자** — 데이터를 만들고 채점한다. 정답지를 볼 수 있다.
- **시험자** — 추이 화면만 본다. 정답지·주입 건수·시나리오 목록·ENGRA 결과를 보지 않는다.
- 한 사람이 둘 다 하면 `sealed/` 를 채점 전까지 열지 않고, 결과에 그렇게 적는다.

## 절차

**1. 생성 (진행자)**

```bash
node tools/baseline/make_shift.js --date 2026-09-14 --kind day
```

화면에 찍힌 네 줄(근무 · `shift.csv` · `tag_master.csv` · 정답지의 SHA-256)을 **시험 전에** 시각이 남는 곳
(이슈·메신저)에 적는다. 날짜는 아무 날이나 된다. 같은 근무 폴더가 이미 있으면 앞선 정답지를 덮지 않도록 멈춘다.

**2. 시험 (시험자)**

- `tools/baseline/viewer.html` 을 Chrome 으로 연다(파일을 바로 열어도 된다). 「파일 열기」에서 생성 폴더의
  `shift.csv` 와 `tag_master.csv` 를 **한 번에 함께** 고른다. 태그 마스터 없이는 열리지 않는다.
- 시험자에게 주는 지시는 이것 하나다 — *「12시간 근무 데이터에서 다음 근무에 인계해야 할 변화(이상 징후나 운전 변화)를 찾아, 찾을 때마다 기록하세요.」*
  정답지에는 탱크 출하 같은 계획 운전도 들어 있고 채점은 엔진과 똑같이 이것도 찾을 대상으로 센다. 그래서 「이상」만 찾으라고 하지 않는다.
- 「시작」을 누르면 추이가 보이고 시간이 흐른다. 변화를 판단할 때마다 태그·시작·끝·종류를 기록한다.
  끌어서 확대한 뒤 「보이는 구간 넣기」를 누르면 시각이 채워진다.
- 다 봤다고 판단하면 「종료」(두 번) → 「기록 내보내기」. 내보내기는 종료한 뒤에만 된다.
  시간 상한을 둘 거면 진행자가 미리 정하고 결과에 적는다.
- 뷰어 말고 다른 도구나 AI 는 쓰지 않는다. 시험 중에 PC 시계를 바꾸지 않는다(경과 시간을 시계로 잰다).
- 새로고침해도 같은 파일이면 기록과 시작 시각이 남는다. 같은 파일로 **다른 사람이 다시** 하려면 「새 시험」(두 번)으로 앞 기록을 지운다.

**3. 채점 (진행자)**

```bash
python3 tools/baseline/compare.py tools/out/baseline/2026-09-14-day --engra --human 기록_2026-09-14-day_이니셜.json
```

`--engra` 만 주면 엔진 쪽만, `--human` 만 주면 사람 쪽만 잰다. 아래 중 하나라도 걸리면 이유를 모두 보여 주고 채점하지 않는다.

- 봉인 값이 지금 파일과 다르다 / 태그 마스터가 엔진 정본(`docs/tag_master.csv`)과 다르다
- 기록지가 다른 CSV·다른 태그 마스터로 작성됐다 / 종료하지 않고 내보냈다 / 시작·종료·경과가 서로 맞지 않는다
- 발견 번호 중복 · 근무 밖 구간 · 끝이 시작보다 앞섬 · 목록에 없는 태그나 종류 · 시험 시간 밖 발견 시각

## 같은 규칙으로 재는 것

- **탐지** — 기록 한 줄(엔진은 이벤트 한 건)이 주입 구간과 시간이 겹치고 태그가 그 시나리오의 영향 태그면 탐지,
  어느 주입과도 안 맞으면 오탐. 1초라도 겹치면 인정하므로 **시각 일치(IoU)** 를 함께 낸다. 표에서 계획 운전은 「(운전)」으로 표시된다.
- **분모** — 정답지만 보고 정한다. 근무 끝을 넘기는 주입은 양쪽 모두 분모에서 빼고, 잡았는지만 따로 적는다.
- **발견 시각** — 둘 다 데이터를 불러온 뒤부터 잰다. 사람은 「시작」부터 기록마다 몇 초에 찾았는지가 붙고,
  ENGRA 는 적재를 마친 뒤 검출·초안이 끝나는 순간 결과가 한꺼번에 나오므로 모든 적중에 그 시각을 붙인다(적재 시간은 따로 적는다).
  둘 다 첫 발견 · 마지막 발견 · 10분 단위 누적으로 낸다.

## 인용할 때 붙이는 조건

- 한 사람이 한 번 한 결과는 **파일럿 관찰**이다. 「사람 대비 몇 배」 같은 일반화로 쓰지 않는다.
- ENGRA 시간은 `ENGRA_LLM=off` 로 **AI 문장 단계를 뺀 시간**이다. AI 단계까지 재려면 `--llm cli`.
- ENGRA 는 새 DB·지난 근무 없이 돈다(기준선 잠정). 라이브는 이력이 쌓인 상태라 조건이 다르다.
- 시험자가 팀원이면 시나리오 종류를 이미 안다 — 사람 쪽에 유리하게 기운 조건임을 적는다.
- 뷰어는 12시간을 한 화면에 보여 주고 3초짜리 튐도 지우지 않게(구간 최소~최대) 그린다. 사람에게 유리한 쪽으로 만든 화면이다.

## 산출물은 커밋하지 않는다

생성·채점 결과는 전부 `tools/out/` 아래에 생기고 `.gitignore` 대상이다. `main` 은 Pages 로 공개되므로
정답지·기록지·DB 를 `main` 에 올리지 않는다.
